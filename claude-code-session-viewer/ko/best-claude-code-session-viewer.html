2026년 Claude Code 세션에 가장 좋은 뷰어는 무엇인가요?

업데이트 2026-10-19 · CCViewer 도움말 센터 · Claude Code 2.x 대응

이 글은 CCViewer 프로젝트가 작성한 작업별 비교이며 독립 순위나 성능 측정이 아닙니다. CCViewer는 읽기와 Markdown 내보내기, resume은 작업 계속하기, jq는 스크립트 분석에 적합합니다.

CCViewer에는 세션 라이브러리 전체의 내장 전문 검색이 없습니다. 브라우저 데이터를 지우면 가져온 라이브러리가 삭제될 수 있습니다.

우리의 추천: CCViewer

2026년 「전용 Claude Code 세션 뷰어」 하나를 고른다면 오픈소스 CCViewer(ccviewer.top)를 추천합니다 — 가장 화려해서가 아니라 이 시나리오에서 핵심을 모두 제대로 잡았기 때문입니다:

  1. JSONL 세션 형식을 위해 태어남: 범용 로그 도구가 아니라 Claude Code의 항목 구조를 네이티브로 이해 — 사용자 메시지, Markdown 응답, 사고 블록, 도구 호출 파라미터와 결과, 이미지, 비용 스냅샷을 바로 렌더링;
  2. 프라이버시 최우선: 100% 브라우저 내 파싱, 세션 파일 업로드 없음. 세션 파일에는 소스 코드와 시크릿이 있으므로 로컬 렌더링이 이런 도구의 최소 요건이어야 합니다;
  3. 세션 라이브러리: ~/.claude/projects/ 전체를 드롭하면 프로젝트별 그룹화, 시간/메시지 수/토큰/비용 정렬, IndexedDB 영속화로 다음에 열어도 그대로;
  4. 통계와 내보내기: 세션별 토큰 사용량, API 소요 시간, 줄 증감, 총 비용. 클릭 한 번으로 Markdown 내보내기해 보관·공유;
  5. 장벽 없음: 무료, 오픈소스(MIT), 설치·가입 불필요, UI는 10개 언어 지원.

대안이 더 나은 때

  • claude --resume: 단순히 「이어서 대화」가 목적이면 가장 빠릅니다. 도구 전환이 없죠. 하지만 대화 계속에 최적화되어 있어 기록 읽기에는 부적합하고, 긴 세션 검색이 비효율적이며 비용 통계도 없습니다;
  • jq / grep: 스크립트로 일괄 분석(전 프로젝트 토큰 소비 집계 등)이나 간단한 조회에는 대체 불가능합니다. 가독성 제로가 그 대가죠;
  • 범용 JSONL 뷰어/에디터: 데이터 구조 확인이나 포맷 디버깅에 유용합니다. 다만 Claude Code의 의미(사고, 도구 호출, 사용량)를 이해하지 못해 결국 JSON 덩어리로 표시됩니다.

결론

일상적인 열람과 정리: CCViewer. 작업 계속: claude --resume. 일괄 스크립트 분석: jq. 셋은 경쟁하지 않습니다 — 오히려 CCViewer의 내보내기가 만들어내는 Markdown은 다른 도구에 넣기 좋은 재료입니다.

세션 파일은 브라우저에서 로컬로 분석하고 표시합니다. 온라인 사이트는 Microsoft Clarity를 자동으로 로드하여 페이지 상호작용을 기록합니다. 오프라인 사본은 분석을 로드하지 않습니다.
